# Персонализация ассистента

## Назначение, scope и владение

Эта спецификация определяет профиль пользователя AI-бариста: набор выбранных
пользователем правил роли и предпочтений, который автоматически участвует в
каждом основном ответе. Профиль помогает одному пользователю получать
стабильный формат и фокус ответа во всех своих чатах.

Она дополняет [базовую спецификацию агента](../barista-agent/SPEC.md) и
[спецификацию слоёв памяти](../memory-layers/SPEC.md). Эта спецификация —
единственный владелец состава, управления, жизненного цикла и видимого
состояния профилей. `memory-layers` владеет композицией контекста основного
ответа и определяет, как активный профиль добавляется к prompt. Профиль не
является памятью, не извлекается из беседы и не изменяется автоматически.

В scope: встроенные и кастомные профили, выбор одного активного профиля,
ручное создание и удаление, применение предпочтений к ответу и изоляция
данных browser-сеансом. Не входят: редактирование встроенных профилей,
автоматическое извлечение или предложение предпочтений, импорт/экспорт,
общий профиль между browser-сеансами, отдельные deep links к профилю и
ограничение длины каждого текстового поля. Последнее намеренно: задание требует
свободного текста без длинового лимита; риск чрезмерного контекста остаётся
открытым для отдельного продуктового решения.

## Профили и основной сценарий

У каждого browser-сеанса есть набор профилей и ровно один активный профиль;
он применяется ко всем проектам и чатам этого сеанса. Смена активного профиля
вступает в силу для следующей отправки, не редактирует уже принятые сообщения,
не изменяет факты памяти и не требует смены проекта или чата.

При первом доступе доступны два неизменяемых встроенных профиля:

| Имя | Стиль | Ограничения | Дополнительный контекст |
| --- | --- | --- | --- |
| Бариста | Дружелюбный, практичный и пошаговый. | Не выдумывай оборудование и ингредиенты; уточняй недостающие параметры рецепта. | Ассистент отвечает как специалист по приготовлению кофе и помогает с выбором напитка, рецептом и техникой заваривания. |
| Специалист по кофейному оборудованию | Технический, структурированный и диагностический. | Не обещай исправить неисправность без данных; предупреждай о рисках при работе с электрическим оборудованием. | Ассистент отвечает как специалист по кофейному оборудованию и фокусируется на подборе, настройке, уходе и диагностике оборудования. |

Активным по умолчанию является профиль «Бариста». Встроенные профили нельзя
переименовать, изменить или удалить.

Пользователь открывает отдельную форму профилей, выбирает встроенный или
существующий кастомный профиль либо создаёт новый. Кастомный профиль содержит:

| Поле | Правило |
| --- | --- |
| Имя | Обязательная строка после trim, не длиннее 60 Unicode-символов и уникальная после trim без учёта регистра среди профилей сеанса. |
| Стиль | Обязательный свободный текст, содержащий хотя бы один символ после trim; ограничения длины нет. Он задаёт желательный тон и форму ответа. |
| Ограничения | Обязательный свободный текст, содержащий хотя бы один символ после trim; ограничения длины нет. Он задаёт недопустимые для ответа подходы или содержательные границы. |
| Дополнительный контекст | Обязательный свободный текст, содержащий хотя бы один символ после trim; ограничения длины нет. Он задаёт устойчивую информацию, полезную для ответов. |

При успешном создании кастомный профиль сохраняется и становится активным.
Пустое имя, стиль, ограничения или дополнительный контекст, имя длиннее 60
символов либо неуникальное имя
не создают профиль и возвращают понятный validation outcome; введённые данные
остаются в форме для исправления. Ошибка сохранения не создаёт и не выбирает
профиль и возвращает безопасный storage outcome.

Пользователь может удалить только кастомный профиль. Удаление всегда требует
явного подтверждения; отмена и ошибка сохранения ничего не меняют. Если удалён
активный профиль, активным сразу становится «Бариста»; если удалён другой
профиль, активный не меняется.

## Правила применения

Для каждого основного ответа агент автоматически использует стиль, ограничения
и дополнительный контекст активного профиля как единое правило более высокого
приоритета, чем инструкции в текущем сообщении и данные памяти. Порядок
приоритета: `активный профиль > текущий чат > project memory > global memory`.
Это намеренное правило
продукта: разовая просьба, конфликтующая с профилем, не отменяет профиль.
Неизменяемые правила безопасности системы сохраняют свой приоритет над всеми
пользовательскими данными.

Тексты трёх полей — недоверенные данные. Они не дают права менять системные
правила, исполнять HTML, вызывать инструменты, получать данные другого
browser-сеанса или раскрывать credentials. Ассистент не заявляет, что выполнил
несовместимую с активным профилем инструкцию.

<!-- ac-section: external-contract -->
## Внешнее состояние и контракты

Чтение состояния текущего browser-сеанса возвращает список профилей, признак
их встроенности, значения стиля, ограничений и дополнительного контекста, а
также идентификатор активного профиля. Список содержит оба встроенных профиля
и все сохранённые кастомные профили владельца.
Создание, выбор и удаление возвращают подтверждённое server-состояние либо
безопасную категорию ошибки; они не раскрывают внутренние ошибки провайдера
или credentials.

Форма предоставляет отдельные действия создания, выбора и удаления. Удаление
недоступно для встроенных профилей. Перед деструктивным действием интерфейс
явно сообщает имя удаляемого кастомного профиля и последствия для активного
профиля, если они есть.

<!-- ac-section: states-and-errors -->
## Состояния, ошибки и наблюдаемость

Пока список профилей загружается, форма показывает loading state и не выдаёт
отсутствующие данные за пустой список. При недоступности сети либо ошибке
чтения/записи пользователь получает отдельный actionable статус с возможностью
повторить своё явное действие; автоматического повтора нет. Существующий
подтверждённый активный профиль и список не заменяются частичным результатом
ошибочной операции.

Каждое чтение, создание, выбор и удаление профиля, а также основной ответ,
содержащий профиль, логируются структурированно с correlation ID, результатом,
категорией ошибки и длительностью при наличии. Логи не содержат credentials,
raw user/assistant text или raw тексты полей профиля.

<!-- ac-section: adaptive -->
## Адаптивность и доступность

На ширине 390 px и 1440 px форма профилей, длинный список и неограниченный по
длине текст каждого из трёх полей не создают горизонтальную прокрутку viewport;
длинный текст переносится или получает собственную прокрутку. Выбор, создание,
подтверждение удаления, отмена и validation/error outcomes доступны с
клавиатуры, touch и мышью и программно объявляются assistive technology.

<!-- ac-section: permissions -->
## Изоляция, безопасность и приватность

Профили принадлежат browser-сеансу/cookie. Они переживают refresh и restart
backend только у того же владельца; другой browser-сеанс не может читать,
создавать, выбирать или удалить их. Persisted state не содержит credentials.
Стиль, ограничения и дополнительный контекст не попадают в global или project
memory и не становятся доступными другому владельцу через диагностику или логи.

<!-- ac-section: performance -->
## Свежесть, производительность и восстановление

Следующий основной запрос после успешного выбора или создания использует
подтверждённый активный профиль. После refresh или restart восстанавливаются
все профили и подтверждённый активный профиль владельца. При offline refresh
показывается последнее принятое server-состояние; непредставленная форма и
незавершённые операции не восстанавливаются как успешные изменения.

Отдельный числовой latency-бюджет для операций с профилями не установлен:
производительность зависит от хранилища и провайдера. Проверяемая цель —
следующий основной вызов использует сохранённые значения всех трёх полей
активного профиля; метод проверки — controlled provider inspection. Deep links
к профилю — N/A, поскольку URL не является контрактом выбора профиля.

## Acceptance criteria

- **AC-PER-01.** В новом browser-сеансе существуют ровно два неизменяемых
  встроенных профиля, «Бариста» и «Специалист по кофейному оборудованию», и
  активен «Бариста». Проверка: browser + API contract.
- **AC-PER-02.** Пользователь создаёт кастомный профиль с уникальным именем до
  60 Unicode-символов и тремя непустыми после trim свободными текстами —
  стиль, ограничения и дополнительный контекст — без лимита длины; профиль
  сохраняется и становится активным. Пустое любое из четырёх полей, имя из 61
  символа и имя, совпадающее с существующим после trim без учёта регистра, не
  меняют список или активный профиль и дают validation outcome. Проверка: API
  contract + browser fixture.
- **AC-PER-03.** Один и тот же запрос в новом чате с профилем «Бариста» и с
  профилем «Специалист по кофейному оборудованию» отправляется controlled
  provider со всеми тремя различающимися полями активного профиля; после смены
  профиля следующий запрос использует только три поля нового профиля. Проверка:
  controlled provider inspection + browser.
- **AC-PER-04.** При конфликте активного профиля, явной инструкции текущего
  сообщения и global/project memory основной запрос и ответ следуют профилю;
  неизменяемое правило безопасности системы остаётся выше профиля. Проверка:
  controlled provider + browser fixture.
- **AC-PER-05.** Встроенный профиль нельзя изменить или удалить. Удаление
  кастомного профиля требует подтверждения: отмена и storage error не меняют
  список или активный профиль; удаление активного кастомного профиля выбирает
  «Бариста», а неактивного — сохраняет текущий выбор. Проверка: browser + API
  contract + persistence integration.
- **AC-PER-06.** Refresh и backend restart восстанавливают список, все три поля
  и активный профиль только для той же cookie; другая cookie не получает ни
  одного кастомного профиля или текста его полей. В persisted state и
  диагностических событиях нет credentials и raw profile-field text. Проверка:
  persistence integration + log inspection.
- **AC-PER-07.** На 390 px и 1440 px форма и текст каждого из трёх полей не
  создают горизонтальный overflow viewport; загрузка, validation, результат
  создания, выбора и удаления доступны клавиатурой и screen reader. Проверка:
  browser accessibility test.

## Открытые gaps

- **Gap-PER-01 — owner: Human.** Не задан продуктовый механизм контроля
  чрезмерно длинных текстов трёх полей при отсутствии лимитов. Он блокирует
  введение абсолютного performance-бюджета и политики обработки переполнения
  контекста, но не блокирует MVP-контракт без ограничения длины.

Подготовка этой спецификации не включает изменения исходников, тестов,
конфигурации, runtime-данных, Git-ветки или запуск разработки.
