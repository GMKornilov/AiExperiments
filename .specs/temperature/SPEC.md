# Вкладка «Температура»: управление вариативностью одного запроса

## Назначение и владение

Вкладка «Температура» (`Неделя 1, задание 4`) позволяет отправить один свободный prompt в настроенную LLM с явно выбранным значением параметра `temperature` и увидеть один текстовый ответ. Она предназначена для ручного сравнения вариативности генерации, но не обещает повторяемость или различие ответов: итог зависит от модели и провайдера.

Эта спецификация владеет поведением страницы `/temperature`, её входным контрактом, результатом и путём API `/api/temperature`. Общая навигация и её список вкладок принадлежат [спецификации алгоритмов](../algorithm-prompt-comparison/SPEC.md). Поведение AI-бариста, его режимы и `/api/chat` остаются в [спецификации бариста](../barista-web/SPEC.md); алгоритмические методы и `/api/algorithms/*` остаются в [спецификации алгоритмов](../algorithm-prompt-comparison/SPEC.md). Эти endpoint не являются альтернативами друг другу и не меняются.

## Страница и пользовательский сценарий

- В общей навигации есть доступная с клавиатуры вкладка `Температура`, ведущая на `/temperature`, с подписью `Неделя 1, задание 4`. Текущая вкладка однозначно обозначена визуально и программно.
- `GET /temperature` открывает пустую форму с одним многострочным полем `Промпт` и управлением `Температура`; других пользовательских полей, режима, истории или скрытых повторных запросов нет.
- `Промпт` обязателен после trim, принимает от 1 до 4 000 Unicode-символов. Enter добавляет перевод строки. У поля есть русская label, сообщение валидации и видимое состояние фокуса.
- Быстрый выбор содержит ровно три доступные с клавиатуры кнопки: `0`, `0.7`, `1.2`. Нажатие каждой немедленно устанавливает соответствующее числовое значение в едином управлении температуры и явно отмечает выбранную кнопку.
- Пользователь также может ввести температуру вручную как десятичное число. Допустимо только конечное число в диапазоне от `0` до `2` включительно; экспоненциальная запись допустима, если после разбора представляет такое число. Пустое значение, нечисловой текст, `NaN`, бесконечность и число вне диапазона не запускают запрос и получают понятное сообщение с допустимым диапазоном. Быстрый выбор не ограничивает ручной ввод только тремя значениями.
- По умолчанию установлена температура `0.7`. При изменении числа вручную ни одна быстрая кнопка не отмечена, если число не равно в точности `0`, `0.7` или `1.2`.
- Только кнопка `Отправить` запускает запрос. При валидной форме она создаёт неизменяемый снимок `{prompt, temperature}` и выполняет ровно один запрос. Изменение полей после нажатия не меняет работающий запрос или его результат; пока он выполняется, повторный запуск недоступен.
- У страницы определены состояния empty, loading, success и error. Успешный ответ показывается как текстовый Markdown без исполнения raw HTML и без загрузки внешних изображений. Ошибка показывает безопасное понятное действие `Повторить`; prompt и текущая температура остаются доступными для правки. Предыдущий успешный результат заменяется началом следующего валидного запуска.
- Черновик и текущий результат существуют только в рамках открытой страницы: reload, новая сессия и прямое открытие `/temperature` начинают с пустого prompt, температурой `0.7` и без результата. Постоянной истории нет.

## API-контракт

Браузер обращается только к same-origin `POST /api/temperature`. BFF проверяет и нормализует запрос, затем передаёт его на приватный Go API `POST /api/temperature`; приватный адрес backend и учётные данные LLM не доступны браузеру. Оба слоя принимают одинаковый контракт и не кэшируют результат.

Request:

```json
{"prompt":"Придумай короткий слоган","temperature":0.7}
```

- `Content-Type` — `application/json`.
- Тело содержит ровно поля `prompt` и `temperature`, без неизвестных полей и второго JSON-значения, и не превышает 64 KiB.
- `prompt` — строка, непустая после trim и длиной не более 4 000 Unicode-символов. В LLM передаётся нормализованное значение без окружающих пробелов.
- `temperature` — JSON number, представляющий конечное значение `0 ≤ temperature ≤ 2`. Строки, `null`, булевы значения и числа вне диапазона невалидны.

Success `200`:

```json
{"answer":"Вкус в каждой чашке."}
```

`answer` — непустая строка, полученная из первого ответа провайдера после удаления окружающих пробелов. В нём не добавляются структурированный JSON, trace или данные другого запроса. Для одного принятого запроса backend делает ровно один вызов настроенного OpenAI-совместимого Chat Completions API с тем же `model`, одной пользовательской репликой `prompt` и числовым параметром `temperature`, равным принятому значению. System prompt AI-бариста, JSON Schema и `response_format` не используются.

Ошибки всегда возвращают JSON `{"error":"<безопасное сообщение>"}` и `Cache-Control: no-store`:

| Причина | Статус |
| --- | --- |
| Некорректный content type | 415 |
| Невалидное тело, пустой/слишком длинный prompt или температура вне контракта | 400 |
| Тело больше 64 KiB | 413 |
| Таймаут, недоступность LLM или невалидный ответ провайдера | 502 |

`POST /api/temperature` — отдельная возможность API. Он не принимает `mode`, `statement`, `language`, и не вызывает `/api/chat` или `/api/algorithms/*`.

## Границы, свежесть и безопасность

- Каждый submit независим: контекст, история и результаты предыдущих запросов не передаются модели. Streaming, отмена, выбор модели и пакетный запуск не поддерживаются.
- Время одного вызова ограничено существующим общим бюджетом LLM-запроса: 30 секунд по умолчанию или положительным `request_timeout` из конфигурации. BFF ждёт backend не более 35 секунд, включая получение тела ответа.
- Prompts, температуры и ответы не записываются в постоянную историю. Штатные application-логи и безопасные ошибки не содержат prompt, answer, учётные данные или приватный URL.
- Отдельных пользователей, ролей, workspace, project и asset в продукте нет. Вкладка не производит деструктивных операций и не запрашивает новые permissions.
- Поддержка температурного диапазона `0–2` опирается на контракт параметра Chat Completions из [официального справочника OpenAI](https://developers.openai.com/api/reference/resources/chat). Если выбранный OpenAI-совместимый провайдер не поддерживает этот параметр или диапазон, запрос завершается безопасной ошибкой без автоподбора другого значения.

## Acceptance criteria

<!-- ac-section: core-flow -->
### Основной поток

- AC-CORE-01: `GET /temperature` содержит только поле `Промпт`, единое управление температуры, три быстрые кнопки и кнопку `Отправить`; подпись навигационной вкладки равна `Неделя 1, задание 4`; проверка — browser-тест и accessibility tree.
- AC-CORE-02: начальная температура равна `0.7`; нажатие `0`, `0.7` или `1.2` устанавливает точно это число и отмечает только соответствующую кнопку; ручной ввод `0.3` сохраняется и не отмечает быструю кнопку; проверка — browser-тест всех четырёх сценариев.
- AC-CORE-03: валидный submit создаёт ровно один запрос с неизменяемым `{prompt, temperature}`; изменение формы во время loading не меняет отправленное тело, а повторная кнопка недоступна; проверка — browser-тест с задержанным подменённым endpoint и счётчиком запросов.
- AC-CORE-04: один успешный запрос к `/api/temperature` создаёт ровно один upstream Chat Completions request с одной user-репликой, настроенной моделью и точно переданным числовым `temperature`; проверка — интеграционный тест с подменённым провайдером, разбирающий тело запроса.
- AC-CORE-05: успешный `{"answer":"  текст  "}` отображается как Markdown `текст`; raw HTML не создаёт DOM-элемент и внешнее изображение не запрашивается; проверка — browser-тест с вредоносной Markdown fixture.

<!-- ac-section: api-contract -->
### Контракт и валидация API

- AC-API-01: BFF и private API принимают только JSON-объект из полей `prompt` и `temperature`, нормализуют prompt и передают одинаковый валидный снимок; проверка — контрактные тесты обоих слоёв с `0`, `0.7`, `1.2`, `0.3` и `2`.
- AC-API-02: пустой prompt, 4 001 Unicode-символ, дополнительные/отсутствующие поля, второй JSON-документ, строковая температура, `null`, `NaN`, бесконечность, `-0.1` и `2.1` возвращают документированный 400/413/415 без LLM-вызова; проверка — параметризованные тесты и счётчик подменённого провайдера.
- AC-API-03: endpoint не принимает `mode`, `statement` или `language` и не обращается к endpoint бариста либо алгоритмов; проверка — интеграционный тест с endpoint-spy.
- AC-API-04: upstream timeout, сетевая ошибка, не-2xx, не-JSON, пустой `choices` или пустой первый текст возвращают безопасную ошибку без URL, тела провайдера или секрета; проверка — параметризованный интеграционный тест с тестовым секретом.

## Out of scope

- Автоматическое сравнение нескольких температур, оценка качества, история, экспорт и сохранение результатов не входят в задание: вкладка исполняет один запрос за один submit.
- Переопределение prompt-моделей, режима AI-бариста, schema, роли модели и настроек провайдера не входит в контракт: пользователь управляет только `temperature`.
- Поддержка иных диапазонов или семантики параметра у конкретного провайдера не добавляется. Их изменение требует отдельного продуктового решения и обновления этой спецификации.
