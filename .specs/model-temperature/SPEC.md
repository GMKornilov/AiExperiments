# Вкладка «Модели»: сравнение трёх моделей

Вкладка «Модели» (`Неделя 1, задание 5`) отправляет один prompt параллельно
в DeepSeek V4 Flash, DeepSeek V4 Pro и Kimi K3 и показывает три Markdown-ответа
с временем, токенами и стоимостью. История и скрытые повторные запросы не создаются.

## Параллельное сравнение

- Единственная кнопка «Сравнить 3 модели» использует текущий непустой prompt
  до 4 000 символов. Все три модели получают один снимок с температурой 1.
  Провайдер, модель и температура не редактируются; одиночного запуска в UI нет.
- Frontend одновременно отправляет три независимых запроса в существующий BFF;
  backend-контракт не меняется. Нет последовательного ожидания или автоповторов.
- Каждая именованная карточка независимо показывает loading, Markdown-ответ
  с временем/входными токенами/выходными токенами/стоимостью либо ошибку.
  Карточки имеют стабильный порядок Flash, Pro, K3; ответы видны сразу по готовности.
- Пока хотя бы один запрос выполняется, новый тройной запуск запрещён.
  Редактирование формы не меняет уже отправленный снимок.
- Ошибка сразу имеет отдельную кнопку повтора, независимо от запросов других моделей:
  повторяется только эта модель с исходным prompt и температурой, без потери
  успешных ответов. Повтор — новый оплачиваемый запрос.
  Для каждой модели допускается только один активный запрос; повторные клики
  не создают дубликатов. Ретраи разных моделей могут выполняться одновременно.
- Карточки расположены в три колонки на широком экране и вертикально на узком.
  Метрики ошибок не подменяются нулями: стоимость неуспешного запроса неизвестна.
- AC-COMPARE-01: до первого ответа отправлены ровно три запроса с одинаковым prompt,
  температурой 1 и точными provider/model.
- AC-COMPARE-02: один ответ и одна ошибка отображаются, пока третья модель ещё
  загружается; повтор ошибки не вызывает успешные модели.
- AC-COMPARE-03: две ошибочные модели можно повторить одновременно, пока третья
  ещё загружается; общий submit заблокирован до завершения всех активных запросов.

## Страница и сценарий

- Общая навигация содержит вкладку `Модели` (`/models`) с подписью
  `Неделя 1, задание 5` и корректным `aria-current`.
- Форма содержит только обязательный `Промпт` и submit-кнопку `Сравнить 3 модели`.
  Enter в textarea добавляет строку. Имена трёх моделей и температура 1 показаны
  в пояснении. Новый запуск заменяет предыдущие результаты.
- Состояния: empty, loading, success и actionable error с кнопкой `Повторить`.
  Ответ показывается как безопасный Markdown. Успех также показывает время ответа
  LLM в миллисекундах/секундах, входные и выходные токены и стоимость в USD.
  Данные существуют только в памяти открытой страницы и очищаются при reload.

## API-контракт

Для сравнения DeepSeek V4 Flash/Pro отправляются с thinking.type=disabled.
Kimi K3 остаётся в обязательном thinking-режиме с reasoning_effort=low.
UI явно показывает эту разницу; prompt и температура остаются прежними.
Для /api/model-temperature используется отдельный model_request_timeout:
по умолчанию 180 секунд, допустимо (0; 180] секунд. BFF ждёт до 190 секунд,
включая чтение ответа. Остальные задания сохраняют прежние настройки.
AC-TIMEOUT-01: параметры отключения/снижения reasoning подтверждены тестами
upstream JSON; исходная длинная задача успешно возвращает три ответа с метриками
через Docker Compose и UI без скрытых повторов, подмены моделей или промпта.

При `LLM_LOG_PAYLOADS=true` общий LLM-клиент дополнительно пишет полное тело
отправленного запроса (llm.request), полученное тело ответа (llm.response), а также
текст ошибки и этап сбоя в llm.finish. По умолчанию режим выключен.
Authorization и URL не выводятся, настроенный ключ клиента заменяется на [REDACTED].
Тела содержат пользовательские данные: режим только для осознанной диагностики.
При обрыве пишется полученная часть тела с complete=false; при лимите чтения —
только прочитанная часть. Невалидный usage логируется с числовыми полями.
Тесты проверяют режим on/off, HTTP-ошибку и частичный ответ.

Диагностика: BFF создаёт request_id и передаёт X-Request-ID backend; ID возвращается
в заголовке ответа. Общий LLM-клиент логирует start/finish с ID, моделью,
длительностью, HTTP-статусом и категорией результата (timeout, canceled, network,
http_error, read_error, invalid_response). Невалидная статистика — invalid_usage,
отсутствие ключа — provider_not_configured. BFF отдельно логирует ошибки backend.
В обычном режиме промпты, ответы, ключи, URL и сырые тела ошибок не логируются.
AC-LOG-01: start/finish связаны одним ID; тесты проверяют отсутствие секретов.
Логирование не меняет контракт ответа и не создаёт дополнительных LLM-запросов.

Браузер вызывает same-origin `POST /api/model-temperature`, BFF — такой же
приватный Go endpoint. Тело не превышает 64 KiB и содержит ровно четыре поля:

```json
{"prompt":"Придумай короткий слоган","temperature":0.7,"provider":"deepseek","model":"deepseek-v4-flash"}
```

- `prompt` нормализуется по краям и содержит 1–4 000 Unicode-символов;
- `temperature` — конечный JSON number в диапазоне выбранного провайдера;
- `provider` — `deepseek` или `kimi`, а `model` обязан принадлежать его allowlist;
- неизвестные, отсутствующие поля, второй JSON-документ и иной content type
  отклоняются до обращения к LLM;
- успех: `200 {"answer":"...","metrics":{"duration_ms":1234,"input_tokens":12,"output_tokens":34,"cost_usd":0.0001}}`;
  ошибки: безопасный JSON с `400`, `413`,
  `415` или `502`; ответы не кэшируются.

Backend выбирает provider-specific URL и ключ и выполняет один OpenAI-совместимый
Chat Completions вызов с выбранной `model`, явной `temperature` для DeepSeek и единственной
user-репликой. Kimi использует отдельные `kimi_base_url` и `kimi_api_key`; пустой
Kimi-ключ не мешает старту приложения, но Kimi-запрос безопасно завершается ошибкой.
System prompt, JSON Schema, `response_format`, fallback модели и автоповтор не
используются. Запрос использует `model_request_timeout`; BFF ждёт не более 190 секунд.

`duration_ms` измеряет полный backend-вызов провайдера. Числа токенов берутся из
provider `usage`, а не оцениваются локально. `cost_usd` вычисляется по текущему
официальному тарифу модели, отдельно для cached/uncached input и output. Для
DeepSeek учитывается peak/off-peak по UTC. Kimi: input/cache/output за миллион
токенов — K3 $3/$0.30/$15; K2.7 Code $0.95/$0.19/$4; K2.6 $0.95/$0.16/$4.
Стоимость расчётная, без налогов. Изменение провайдером тарифов требует обновления
таблицы цен и тестов.

## Acceptance criteria

- AC-CORE-01: `/models` показывает prompt и единственную кнопку сравнения;
  selects, редактирование температуры и одиночная отправка отсутствуют.
- AC-CORE-02: submit запускает три независимых запроса с одинаковым prompt
  и температурой 1; каждый ответ — безопасный Markdown с четырьмя метриками.
- AC-API-01: BFF и Go API одинаково принимают только документированный контракт,
  нормализуют prompt и запрещают произвольную либо не принадлежащую провайдеру модель.
- AC-API-02: один успешный запрос создаёт один upstream-вызов с точными provider,
  model и prompt; temperature передаётся для DeepSeek и опускается для Kimi;
  токены берутся из usage (кэш Kimi — usage.cached_tokens), длительность измеряется,
  стоимость соответствует тарифу; ошибки провайдера не раскрывают URL, тело или ключ.
- AC-A11Y-01: prompt имеет label, ошибки доступны через `role=alert`, форма управляется с
  клавиатуры и не создаёт горизонтальную прокрутку на 320 px.

списка или цены требует изменения UI, allowlist обоих API-слоёв, backend-таблицы
цен, тестов и этой спецификации одним изменением.

## Вне задачи

Не входят: произвольный набор моделей для сравнения, несколько температур, vision-ввод,
thinking toggle, streaming, история, оценка ответов, старые Kimi-модели и получение
списка моделей напрямую из браузера.
