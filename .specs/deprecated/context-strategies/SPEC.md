# Стратегии управления контекстом

## Назначение и приоритет

Это SSOT выбора и поведения контекста AI-бариста. Он дополняет
[базовую спецификацию](../barista-agent/SPEC.md) и имеет приоритет над её
прежними правилами о toggle «Сжатие истории», контексте без сжатия и `/compact`.
План сравнений находится в [отдельном сценарии](../../../docs/context-strategies-scenario.md).

В scope: четыре стратегии, явный выбор, facts, ветки, Summary, токены и
сохранение состояния. Не входят: автоподбор или смена стратегии после старта,
ручная правка facts, переименование/удаление/слияние веток, обещание качества
или экономии конкретной модели.

## Правила и выбор

**Сообщение** — завершённая отдельная user- или assistant-реплика; текущий
user-ввод тоже считается сообщением. N задаётся серверной конфигурацией,
фиксируется в новом диалоге, должно быть положительным целым и по умолчанию
равно 10. System prompt не входит в N и всегда включается.

Перед первым сообщением пользователь обязан выбрать доступную карточку
`Sliding Window`, `Facts`, `Branching` или `Summary`; значения по умолчанию нет.
Composer до выбора недоступен. Если конфигурация Facts или Summary отсутствует,
карточка недоступна с причиной, но пользователь выбирает один из остальных
режимов. В пустом диалоге выбор можно изменить, после первого принятого
сообщения — нельзя ни через UI, ни через API.

## Стратегии

| Режим | Контекст chat-вызова |
| --- | --- |
| Sliding Window | System prompt и последние N сообщений линии: текущий input и предшествующие завершённые реплики. Более старое не передаётся модели. |
| Facts | System prompt, валидный facts-блок и последние N сообщений линии: текущий input и предшествующие завершённые реплики. |
| Branching | System prompt и вся линия активной ветки. Summary, facts и N не используются. |
| Summary | System prompt, накопительное summary и несжатый хвост. Автообновление использует N и `batch_size`; ручной `/compact` сворачивает весь хвост. |

Видимая переписка и архив сохраняются во всех режимах, но старый архив не
становится дополнительным источником контекста. Pending и error-реплики не
включаются, кроме текущего принятого user-input в его собственной попытке.
Retry включает этот input ровно один раз.

### Facts

После каждого принятого user-сообщения и до chat сервис вызывает отдельный
facts-экстрактор. Он получает прежние facts и последние N сообщений линии,
включая текущий user-input, как данные, а не полный архив; это позволяет понять
краткое «да, согласен». Он возвращает полный снимок подтверждённых пользователем
целей, ограничений, предпочтений, решений, договорённостей и параметров.
Исправление заменяет старое значение; удалённый факт опускается из нового снимка.

Допустим только один JSON object без Markdown, пояснений, массивов, вложенных
объектов, чисел, boolean и null. Все ключи и значения — непустые строки, ключи
уникальны и lower_snake_case; пустой object разрешён. Facts не имеет
предзаданной схемы: extractor самостоятельно выбирает устойчивые смысловые
категории по подтверждённым данным диалога, объединяет связанные сведения в
связное строковое значение и не создаёт отдельный key для каждой сущности или
элемента списка. При обновлении он сохраняет подтверждённые детали, заменяет
только исправленные сведения и опускает явно отменённые facts. Новый facts-снимок
проходит проверку до сохранения и передаётся chat отдельным явно обозначенным
блоком перед хвостом.
Пользователь видит его в раскрываемом read-only блоке и исправляет ошибку новым
сообщением, а не ручным редактированием.

Если extractor недоступен, истёк timeout или ответ невалиден, прежние facts
сохраняются, chat не вызывается, а user-реплика становится retryable. Retry
после такой ошибки заново извлекает facts и затем запускает chat. Если facts
уже успешно обновлены, а ошибка произошла в chat, retry использует этот снимок
и не вызывает extractor повторно. Невалидная память не передаётся основной модели.

### Branching

В режиме Branching sidebar показывает под чатом `Основная ветка` и вложенные
`Ветка 1`, `Ветка 2` и далее. «Добавить ветку» доступно только после успешной
assistant-реплики активной линии. Действие копирует всю активную линию по её
последнее завершённое сообщение, создаёт и выбирает новую ветку без LLM-вызова.
При пустой, pending или error-линии кнопка недоступна с причиной.

Каждое добавление берёт текущую активную линию. Две ветки от одной точки
получаются, если вторую создать до нового сообщения в первой, либо вернуться к
общей линии. После этого ответы, ошибки и retry веток независимы: соседние
сообщения не показываются и не передаются модели. Переключение ветки не вызывает
LLM.

### Summary и `/compact`

Summary сохраняет существующее автоматическое накопление summary и хвоста;
`batch_size` фиксируется в новом диалоге. `/compact` виден и исполняется только
в Summary. Во всех других режимах backend отклоняет даже прямой compact-запрос
как валидационный без upstream-вызова. Успех и ошибка `/compact` не меняют
стратегию.

## Контракты и сохранение

Создание диалога принимает обязательный `context_strategy`:
`sliding_window`, `facts`, `branching` или `summary`. Пустое, невалидное,
недоступное значение и попытка смены после старта дают безопасную validation
error без изменения состояния. Чтение возвращает выбранную стратегию.

У Branching чтение возвращает `active_branch_id`, ветки с ID, именем,
родительской точкой и числом сообщений, а `messages` — линию активной ветки.
API поддерживает создание ветки из активной линии и выбор существующей ветки.
У Facts чтение возвращает валидный `facts` object. Все операции наследуют
владение browser-сеансом диалога.

Сервер хранит и восстанавливает стратегию, снимок N, facts, summary, ветки,
активную ветку, transcript и usage после refresh/restart. Снимки facts- и
summary-конфигурации сохраняют параметры, но никогда credentials. Удаление
диалога удаляет всю его память по действующим правилам.

## Состояния, наблюдаемость и токены

| Ситуация | Результат |
| --- | --- |
| Нет выбора | Отправка недоступна. |
| Facts error | Старые facts сохранены; chat не вызван; доступен retry. |
| Создание/выбор ветки | Возвращается подтверждённое сохранённое состояние; LLM не вызвана. |
| `/compact` вне Summary | Понятный отказ, память и usage не меняются. |
| Offline | Refresh читает принятое server-состояние; auto-retry нет. |

События выбора стратегии, facts extraction, веток и `/compact` содержат
correlation ID, диалог, ветку при наличии, результат, категорию и длительность;
метаданные не содержат secrets. Тела facts-экстрактора подчиняются существующей
политике `log_text_payloads` так же, как chat и summary.

Полный расход сравнения — подтверждённые usage: chat для Sliding Window и
Branching, chat + facts для Facts, chat + summary для Summary. Название
исключено. Неизвестный usage не равен нулю. Создание/выбор ветки не добавляют
расход; в сводке общего диалога общий префикс учитывается один раз.

<!-- ac-section: adaptive -->
## Адаптивность и доступность

На 390 px и 1440 px карточки, facts и вложенные ветки не создают горизонтальную
прокрутку viewport; длинные значения переносятся или имеют собственную
прокрутку. Все действия доступны touch, мышью и клавиатурой. Карточки —
radio-группа с причиной недоступности; выбранные стратегия и ветка имеют
программно определяемое состояние. Status-объявляет facts, ветки и ошибки.

<!-- ac-section: permissions -->
## Права и безопасность

Стратегия, facts и ветки доступны только владельцу диалога; другой browser-сеанс
не может их читать или менять. Существующее `/admin`-исключение по точному ID
не получает новых операций редактирования. User-текст и facts — данные для
экстрактора, не инструкции; строгая проверка JSON происходит до сохранения.
В персистентности и ответах нет credentials; журнал сохраняет действующую
политику `log_text_payloads` без новых исключений.

<!-- ac-section: performance -->
## Производительность и восстановление

Создание и выбор ветки не вызывают LLM. При ожидании facts или Summary UI
показывает понятный progress-status до завершения операции. Проверка: controlled
provider и browser-тест; числовой performance-бюджет требует отдельного измерения
и пока не зафиксирован.

Отдельных branch deep links нет: N/A, URL не является контрактом выбора ветки.
Refresh/restart восстанавливает последний диалог и активную ветку; при её
недоступности открывается Основная. Непринятый local input не восстанавливается.
При offline refresh читает принятое server-состояние; auto-retry отсутствует.

## Acceptance criteria

- **AC-CTX-01.** Сообщение нельзя отправить без явной стратегии; смена после
  первого сообщения отклоняется без изменения памяти. Проверка: browser + API.
- **AC-CTX-02.** При N=3 четвёртый user-вызов Sliding Window содержит system,
  текущий input и ровно два предыдущих завершённых сообщения. Проверка: provider inspection.
- **AC-CTX-03.** Facts обновляются после каждого нового user-input и до его
  chat только валидным плоским `string→string` JSON; исправление заменяет
  прежнее значение. Проверка: integration fixture.
- **AC-CTX-04.** Невалидный/ошибочный facts-response не вызывает chat, хранит
  прежние facts и даёт retry. Проверка: controlled provider.
- **AC-CTX-05.** Две ветки от одной линии имеют общий prefix; сообщения одной
  отсутствуют в UI и LLM-контексте другой. Проверка: integration + browser.
- **AC-CTX-06.** Branching отправляет полную активную линию без facts/summary/N;
  add/select branch не вызывают LLM. Проверка: provider inspection.
- **AC-CTX-07.** `/compact` работает только Summary, включая прямой backend
  запрос; в иных режимах upstream не вызван. Проверка: browser + integration.
- **AC-CTX-08.** Restart восстанавливает всю стратегическую память без
  credentials. Проверка: persistence integration.
- **AC-CTX-09.** Usage разделяет chat/facts/summary, неизвестное не считает
  нулём и не дублирует общий prefix веток. Проверка: fixture usage.
- **AC-CTX-10.** Все четыре стратегии проходят по три прогона 12-message
  сценария; отчёт фиксирует факты, качество, стабильность, usage и удобство
  без обещания результата заранее. Проверка: ручной реальный прогон.

## Исторические диалоги

Совместимость и миграция диалогов без `context_strategy` не требуются.
Пользователь явно разрешил удалить текущую сохранённую историю до включения
функции. Эта запись фиксирует разрешение, но не утверждает, что удаление уже
выполнено.

Подготовка этой спецификации не включает изменения исходников, тестов,
конфигурации окружения, Git-ветки или исторических данных.
