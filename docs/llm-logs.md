# Журнал агента-бариста

Откройте `/admin` и введите точный ID из sidebar чата. Страница показывает события
frontend/BFF и backend отдельными группами. Кнопка «Обновить» читает журнал вручную;
автоматическое чтение выполняется каждые 5 секунд и не создаёт событий polling.
Аутентификации нет, но списка ID всех диалогов также нет.

Журнал и диалоги хранятся только в памяти backend. Удаление диалога стирает его
журнал; перезапуск backend очищает всю память. Уже выведенные строки console остаются.

## Тексты сообщений

В backend YAML задайте `log_text_payloads: true` и перезапустите backend, чтобы
включить запись текстов user/assistant. Значение по умолчанию — `false`.
Переменные окружения этот режим не переключают. `/admin` показывает его состояние.

System prompt, credential, Authorization, содержимое конфигурации и сырые ответы
с ошибками провайдера не записываются. В текстах сообщений значение credential
снимка заменяется на `[REDACTED]`. После диагностики верните флаг в `false`.

## Корреляция и ошибки

Записи содержат timestamp, source, event, result, correlation_id, а при наличии —
dialog_id и message_id. Завершённые операции содержат duration_ms; ошибки — безопасную
error_category. Correlation ID HTTP-запроса возвращается в `X-Request-ID`.
Ошибки до создания диалога доступны через server console.

```sh
docker compose logs -f --since=5m barista-api barista-web
docker compose logs --since=15m barista-api barista-web | rg 'CORRELATION_ID'
```

При локальном запуске смотрите терминалы backend и Next.js. Для записи в файл:

```sh
cd backend
go run ./cmd/api-server --config=config.yaml 2>&1 | tee /tmp/barista-backend.log
```

| Категория | Что означает |
| --- | --- |
| config | Не удалось прочитать или проверить конфигурацию либо prompt |
| validation | Запрос не соответствует контракту |
| network | Соединение не установлено или прервано |
| timeout | Истёк timeout снимка или ожидания BFF |
| provider | Провайдер вернул ошибку |
| invalid_response | Ответ пустой, слишком большой или имеет неверный формат |
| busy | В сеансе уже выполняется попытка либо требуется retry |
| not_found | Диалог отсутствует или недоступен этому браузеру |

Категория описывает наблюдаемый результат, а не доказывает внутреннюю причину.
После ошибки повтор запускается только действием пользователя. Перед повтором
клиент сверяет серверное состояние, чтобы не повторять успешную или pending-попытку.
